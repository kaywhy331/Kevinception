Multi-agent operating system

Agentic Work Fleet

A role-based operating model for coordinating specialized AI agents through shared context, task packets, governance, evidence, handoffs, and explicit human decision gates.

2026–Current
Role

01

The situation

Problem and context

The problem

Multiple AI agents can increase throughput, but without clear roles, canonical context, ownership, review authority, spend controls, and handoff rules they create duplicated work, stale assumptions, attribution drift, and a larger coordination burden for the human operator.

Context

Kevin designed and operates a personal fleet model with specialized strategy, governance, execution, research, processing, and audit roles. Work is coordinated through a versioned vault, task lifecycle, initiative packets, runtime signals, evidence requirements, and escalation surfaces.

Constraints

  • Agents operate across separate hosts, tools, sessions, and authorization boundaries.
  • The system must distinguish agent-owned work from decisions that genuinely require Kevin.
  • No agent should bypass review, release, credential, safety, or consequential-write gates.
  • Context and operating state must survive session boundaries without relying on model memory alone.
02

The work

Approach and decisions

  1. 01

    Defined permanent roles with distinct responsibilities, authority, and output contracts.

  2. 02

    Created a canonical vault and task lifecycle for initiatives, decisions, standards, evidence, and memory.

  3. 03

    Separated strategy, execution, QA/governance, research, and escalation so one agent does not silently approve its own work.

  4. 04

    Added routing, pause, budget, health, stale-work, and recovery policies as explicit operating rules.

  5. 05

    Converted repeated operational failures into standards, automated checks, and product requirements for TokenPak.

Key decisions

  • Kevin owns strategy and irreducible product decisions; the governance role owns routine QA closure.
  • Agents receive the smallest useful authority and context needed for the task.
  • Evidence and handoff quality matter more than raw task count.
  • Automation should reduce Kevin wait states by presenting recommendations and defaults—not simply forwarding open questions.

Learning

  • Agent orchestration is primarily an operations and governance problem before it is a model-selection problem.
  • A system becomes more autonomous when it resolves routine ambiguity safely—not when it removes the human from consequential decisions.
  • Persistent context, evidence, and explicit authority are what turn parallel AI sessions into a coherent operating system.
